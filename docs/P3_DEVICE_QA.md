# P3 真机与数值验收

## 验收版本

```bash
npm run verify
npm run build:web
```

必须使用 `build/web-mobile`，并确认命令最后输出“正式 Web Mobile 构建通过”。测试手机与开发机
处于同一局域网时，用静态服务器暴露该目录后访问开发机局域网地址；不要用编辑器预览代替正式
构建。

## 设备矩阵

至少覆盖以下两台物理设备：

- iPhone：带刘海或灵动岛，Safari，竖屏；
- Android：主流全面屏，Chrome 或系统 WebView，竖屏。

每台设备记录系统版本、浏览器版本、屏幕尺寸、是否高刷新率。模拟器与桌面响应式窗口可作为
回归证据，但不能替代上述物理设备。

## 单设备流程

1. 冷启动：加载页不白屏，弱网资源失败时仍能进入菜单；
2. 首局：教学不被刘海、地址栏或底部手势区遮挡；
3. 战斗：摇杆、点击移动、踏云、剑阵和天劫均能触发；
4. 暂停：计时、敌人、寒潮与冷却冻结，继续后恢复；
5. 后台：切出浏览器五秒再回来，应停在暂停页；
6. 旋转：横屏显示旋转守卫，旋回竖屏后继续原局；
7. 设置：关闭音效与震动后立即生效，重启页面后仍保持；
8. 完整通关：奇遇、Boss 转相、战报和再战按钮无裁切；
9. 三章首破：出现“三境归一”终卷并能返回试炼图；
10. 连续运行：完成三局后无明显掉帧、发热突增或音频叠响。

每一步记录“通过 / 失败 / 无法验证”，失败项附截图、操作步骤和发生频率，不用主观描述替代
复现条件。

## 数值样本

每章至少完成 10 局真人试玩，且两条路线、三类主修均有覆盖。首轮健康区间：

- 胜率：30%–80%；
- 胜利中位局长：2:30–5:00；
- 两条路线均被选择；
- 锋芒、玄术、守元均出现通关样本。

试玩使用无 `qa` 参数的正式地址，系统会保存最近 60 局。完成后在地址追加 `?qaBalance=1`，
点击左上角“平衡”打开报告，再点击“复制样本”。把复制出的 JSON 按“设备-测试人-日期”命名
保存；禁止把 QA 快速胜利数据混入真人样本。

收齐多位测试者的文件后，执行：

```bash
npm run balance:report -- samples/*.json
npm run balance:report -- --strict samples/*.json
```

第一条输出 Markdown 汇总；第二条用于最终验收，只要任一章节样本不足、胜率/局长越界、路线未
覆盖或缺少通关构筑，就以非零状态退出。汇总器接受报告页直接复制的数组，也接受带 `samples`
字段的样本包，并会拒绝字段损坏或未知章节的数据。新版样本包还包含导出时间、浏览器环境和
逐局唯一标识；同一份样本被重复收集时会按唯一标识自动去重，不会虚增验收局数。

## 调参决策

- 胜率低但局长正常：优先降低不可读伤害或增加预警，不先削减敌人总血量；
- 胜率正常但局长过长：优先减少普通波血量或刷新间隔，保留 Boss 机制；
- 单一路线占比过高：比较关底因果与即时收益，不只提高另一条路线的面板数值；
- 单一主修垄断通关：检查 Boss 前构筑检验与技能使用机会，避免全面削弱强势流派。

只有设备矩阵、每章样本量和健康区间都形成证据后，P3 才能标记完成。
